# Инструкция агенту

## Назначение и границы

Windows-процесс на Playwright: управляемый Chrome, чтение HH и разрешённые backend действия.

## Карта кода

- `src/main.ts` — диспетчер; `src/backend` — команды и heartbeat.
- `src/browser`, `src/hh` — Chrome и сценарии HH; `src/generation`, `src/assessment` — AI-помощники.
- `tests` — синтетические страницы и сценарии без настоящего HH.

## Инварианты

- Реальный отклик допустим только из явного запуска и после разрешения backend.
- Перед потенциально отправляющим кликом проверяй URL, vacancy ID и выбранное резюме.
- Не повторяй отправку после потерянного или неопределённого ответа.
- Сохраняй последовательную обработку действий HH; параллельность анализа не переносится на отклики.
- Не заполняй анкеты автоматически и не обходи капчу.
- Embedded JSON поиска допустим только при совпадении ID и порядка со стабилизированным DOM.
- Не передавай HTML, cookies, credentials и сырые Playwright logs в backend или логи.
- Холостой запуск не получает permit отправки и не генерирует письма.

## Изменения и документация

Изменённый контракт одновременно отражай в клиентах, конфигурации, тестах и документации.
Проверяй утверждения по реализации. Не сохраняй планы, историю обсуждений и результаты
конкретных прогонов в постоянных инструкциях. Действующие причины решений описывай в архитектуре.

## Проверка

```powershell
npm.cmd run type-check
npm.cmd run build
node --import tsx --test tests/*.test.ts
```

Команды запуска сервисов и живые проверки не являются автономными тестами.
Условия интеграционных и ручных проверок смотри в документации.
