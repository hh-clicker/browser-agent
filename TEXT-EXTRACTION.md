# Извлечение текстов

Контракты plain-text снимков резюме и вакансии. HTML и пользовательские профили не хранятся в исходниках.

<a name="resume"></a>
## Текст резюме при импорте

Поиск карточек остаётся лёгким: `DISCOVER_RESUMES` без URL возвращает только название и hash.
После выбора frontend последовательно вызывает `POST /api/v1/browser/resume-text`
для отмеченных резюме. Backend ставит `DISCOVER_RESUMES` с каноническим URL печати.
Старый агент не возвращает текст и не сможет молча завершить такой импорт успешно.

Агент проверяет вход и наличие hash среди карточек текущего аккаунта. Затем читает
`https://hh.ru/resume/{hash}?print=true` в отдельной временной вкладке того же профиля.
Вкладка создаётся в фоне, чтобы импорт не перехватывал фокус окна.
Автоматическая печать отключена; загрузка image/media/font блокируется. Вкладка закрывается
после чтения, другие вкладки не закрываются. HTML и initial state в протокол не передаются.

Извлекаются только профессиональные блоки с data-qa: позиция, зарплата, регион/переезд,
специализации, опыт, навыки, языки, о себе, образование и дополнительные условия.
Контактный блок, фото, служебные кнопки, скрытые узлы, скрипты и рекомендации исключены.
Абзацы, списки и переносы pre-line сохраняются, пробелы нормализуются. Изображения/OCR
и генерация писем не используются. Резюме даже с одним коротким названием импортируется:
опыт, образование, навыки и минимальная длина текста не требуются. Полностью пустой текст,
текст более 100 000 символов и неверная страница
дают понятную ошибку с этапом сбоя без содержимого резюме или сырых Playwright call logs.

Все выбранные тексты загружаются до POST `/api/v1/resumes/import`: сбой одного чтения
не оставляет частично импортированную пачку. В БД сохраняются `plain_text`, `text_loaded_at`
(миграция 014). Уже существующие резюме не обновляются и могут иметь null в этих полях.
Настройки откликов не перезаписывают снимок текста. Посмотреть снимок можно в карточке резюме.

Синтетические тесты: `tests/resume-text.test.ts`. Пользовательский HTML не хранится в репозитории.
Для проверки нужно обновить backend, frontend и Browser Agent; открывать реальную вакансию
или отправлять отклик не требуется.

<a name="vacancy"></a>
## Текст вакансии

Во время `APPLY_VACANCY`, после проверки URL и заголовка деталки, но до первого
клика отклика, агент извлекает текст из `[data-qa="vacancy-description"]`.
Перед извлечением агент проверяет архивную отметку в заголовке
`[data-qa="vacancy-title-archived-text"]` и сообщение
`[data-qa="vacancy-archive-description"]` на той же деталке. Для архивной
вакансии текст не извлекается ни в реальном, ни в холостом запуске.
Обычная и брендированная версии используют этот маркер; класс
`vacancy-description-print` может оборачивать видимое брендированное описание.

Сохраняются абзацы, переносы строк, пункты списков и текст ссылок. HTML,
изображения (включая alt), SVG, скрытые элементы, скрипты, управляющие элементы,
баннеры вне описания и рекомендации не сохраняются. Экстрактор не делает
сетевых запросов; обычная навигация страницы HH остаётся без изменений.
Поля карточек выдачи сохраняются отдельно. Самостоятельной таблицы ключевых навыков нет;
если навыки входят в текст блока описания, они остаются частью этого текста.

`vacancyPlainText` передаётся вместе с результатом команды:
- `null`/отсутствует — блок не прочитан; прежний снимок не меняется;
- `""` — распознанный блок не содержит текста, например состоит из картинок;
- непустая строка — снимок текста, до 100 000 символов без обрезки.

Отсутствие текста не запрещает отклик само по себе. При включённом AI используется
непустое резервное письмо; если резерв пуст, создаётся задача внимания без отправки.
При выключенном AI действует обычный сценарий. Снимок также снимается с уже откликнутой вакансии;
повторного отклика и генерации это не вызывает. Если отклик ещё не отправлен и AI включён,
свежий текст передаётся генератору до клика. Для отдельной загрузки описаний используется явный холостой запуск DRY_RUN;
самопроизвольного обхода деталок нет. Подробнее о генерации — в [README](README.md#ai-сопроводительные-письма).

Backend привязывает текст к вакансии из сохранённого application item,
а не к присланному агентом ID. Он сохраняет `vacancy.plain_text` и
`text_loaded_at` в транзакции обработки результата (миграция 015).
Повторная доставка завершённой команды ничего не перезаписывает.
Повторное сканирование выдачи не сбрасывает текст. Текст не включён в массовый
ответ списка вакансий: `GET /api/v1/vacancies/{id}/text` читает только сохранённый
снимок, без обращения к HH. Фронт показывает его в раскрытой строке вакансии
через обычную текстовую интерполяцию, не `v-html`.

Синтетические тесты: `tests/vacancy-text.test.ts`, дополнения в
`tests/application-detail.test.ts` и backend `ApplicationSafetyTests`.
Ни один тест не должен обращаться к настоящему HH или отправлять реальный отклик.
